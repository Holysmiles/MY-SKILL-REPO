# Action Checklists

Use `[x]` only for verified items. Add evidence or a reason after each item.

## Project Selection

- [ ] Strong AI Agent relevance
- [ ] Sufficient community signal for the user's goal
- [ ] Commit within the expected activity window
- [ ] Maintainers respond to Issues
- [ ] Recent PR first-response and merge behavior inspected
- [ ] Release cadence or maintenance model understood
- [ ] README/CONTRIBUTING are usable
- [ ] User stack is a reasonable match
- [ ] A 7-14-day contribution appears feasible

## Issue Selection

- [ ] Label is good first issue/help wanted/bug/documentation/enhancement
- [ ] Issue is open
- [ ] Activity is within 60 days
- [ ] No assignee
- [ ] No active claim or linked implementation
- [ ] Description is clear
- [ ] Expected behavior or reproduction is present
- [ ] Estimated scope is 1-3 files
- [ ] No repository-wide redesign is required

## Before PR

- [ ] README and CONTRIBUTING were read
- [ ] Relevant source and policy/config files were read
- [ ] Baseline behavior was recorded
- [ ] Problem boundary and design were confirmed
- [ ] Maintainer alignment is recorded or validly waived
- [ ] Public API compatibility was checked
- [ ] Relevant tests and demo passed
- [ ] Required documentation was updated
- [ ] No unnecessary dependency was introduced
- [ ] Diff/secret/license/CLA/DCO/AI-disclosure checks passed

## Interview Readiness

- [ ] Project context and selection rationale are clear
- [ ] The discovered problem has evidence
- [ ] Design tradeoffs can be explained
- [ ] Implementation path focuses on decisions
- [ ] Tests and verification can be reproduced
- [ ] PR/result state is current and truthful
- [ ] Concrete technical challenges are documented
- [ ] Technical, process, and scope reflections are specific
- [ ] Claimed capabilities map to evidence
